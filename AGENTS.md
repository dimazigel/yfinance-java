# AGENTS.md

Guidance for AI coding agents working in this repository.

## Project

`yfinance-java`: a Java 21 port of the Python [`yfinance`](https://github.com/ranaroussi/yfinance) library, built on OpenFeign 13 / OkHttp 5 / Jackson 3 with Gradle 9 (Kotlin DSL, version catalog in `gradle/libs.versions.toml`). It is a plain library with no framework dependencies. The package root is `io.github.dimazigel.yfinance`, and it publishes as `io.github.dimazigel:yfinance-java` (GitHub Packages only — Maven Central was considered and declined; see `RELEASING.md`). The public API is described in `README.md`; the field-level contract of the model is `docs/superpowers/specs/2026-09-26-typed-instrument-model-appendix.md` (Appendix A, normative), explained by `…-design.md` and backed by `…-yahoo-field-survey.md`.

## Commands

```bash
./gradlew test                    # unit tests (excludes @Tag("live")) + JaCoCo report
./gradlew test --tests 'io.github.dimazigel.yfinance.internal.service.InstrumentServiceTest'             # one class
./gradlew test --tests 'io.github.dimazigel.yfinance.internal.assembly.build.EquityBuilderTest.samsungLacksBookValueButIsStillAnEquity'  # one method
./gradlew integrationTest         # opt-in live suite against real Yahoo (src/integrationTest, @Tag("live"))
./gradlew build                   # compile (+Error Prone/NullAway/-Werror) + tests + Spotless check + coverage floor + jars; what CI runs
./gradlew spotlessApply           # fix import order / whitespace before committing
./gradlew moduleSmokeTest         # run the library as a JPMS module against a local stub server (part of check)
./gradlew publishToMavenLocal     # install 0.1.0-SNAPSHOT for consuming projects
```

Main code compiles with **Error Prone's default checks + NullAway + `-Werror`**, so any finding fails `compileJava`; test code is compiled without Error Prone. **Javadoc** (`./gradlew javadoc`, part of `build` through the javadoc jar) covers the exported packages only — everything under `internal/` is excluded (`exclude("**/internal/**")`; javadoc resolves the internal types the API sources mention from the compiled classes, patched into the module with `--patch-module`) — and runs doclint at `all,-missing`: a bad `{@link}`, malformed HTML or a wrong `@param` name fails the build, a missing comment does not. Every new public member in an API package still gets Javadoc. **Spotless** pins import order (static first, then one lexicographic block), unused imports, trailing whitespace and final newlines — `./gradlew spotlessApply` fixes, `check` verifies; indentation/wrapping are not enforced, match the surrounding code. `check` also enforces a **JaCoCo floor** of 85 % line / 60 % branch. Dependency scopes: `api` only for types in the public API (OkHttp, JSpecify, slf4j-api); Feign and Jackson are both `implementation` — don't put their types in public signatures (the `@RequestLine`/`@Param` annotations on the `internal/api/` interfaces are the only Feign symbols visible to consumers). Jackson 3 splits its packages: databind and core types live under `tools.jackson.*`, while annotations stay on `com.fasterxml.jackson.annotation` (Jackson 3 keeps that package), so DTO annotations are untouched. The library is a **JPMS module**, `io.github.dimazigel.yfinance` (`src/main/java/module-info.java`): it `exports` exactly the API packages (the root, `batch`, `detail`, `detail.rows`, `enums`, `exception`, `fundamentals`, `http`, `instrument`, `logging`, `market`, `news`, `search`, `valueobject`), exports nothing under `internal`, `requires transitive` only `okhttp3`, `org.jspecify` and `org.slf4j`, and `opens` each `internal.dto.*` package to `tools.jackson.databind` (Jackson builds the wire records reflectively). Unit tests run on the classpath, where encapsulation is off, so `./gradlew moduleSmokeTest` (part of `check`; source set `src/moduleTest`, a consumer module with its own `module-info.java`) runs the library jar as a named module against a JDK `HttpServer` replaying the fixtures, one call per endpoint family. A new exported package needs an `exports`; a new `internal.dto` sub-package needs an `opens` and a call in `ModulePathSmoke`, or the smoke test cannot see it break. Configuration cache, parallel builds and build caching are enabled in `gradle.properties`, so custom Gradle tasks must stay configuration-cache compatible (see `VerifySourcesPublicationTask` in `build.gradle.kts`). Releases are cut by manually running the **Release** workflow (`.github/workflows/release.yml`) on `main`. It bumps the latest tag (patch/minor/major) or takes an explicit version, builds and tests, publishes to GitHub Packages, then creates the tag and GitHub release. Tags have no `v` prefix (`0.0.2`). `publish.yml` still publishes releases created by hand in the GitHub UI, skipping releases authored by `github-actions[bot]`. Both workflows run `.github/scripts/check-published.sh` first and skip publishing if the version already exists in GitHub Packages, so re-running a half-failed release is safe and nothing is ever uploaded twice. `live.yml` runs the live integration suite weekly (and on demand) to detect Yahoo API drift. Both workflows pass the version to Gradle as `-PreleaseVersion` and publish with the explicit `publishAllPublicationsToGitHubPackagesRepository` task. Plain `maven-publish`; the publication is named `mavenJava`.

## Architecture

**Layout:** the API lives in the exported packages directly under the root (`instrument`, `detail`, `batch`, `market`, `fundamentals`, `search`, `news`, `enums`, `exception`, `logging`, `valueobject`, and `http` — which holds only the configuration records `EndpointConfig`/`AdaptiveRateLimitConfig`/`RetryConfig` and `InMemoryCookieJar`). Everything else lives under `internal/` (`api`, `assembly`, `auth`, `batch`, `dto`, `http`, `mapper`, `service`) and is not exported. Put a new class under `internal/` unless a consumer has to name it. A public type in an exported package must not mention an `internal` type in a public or protected signature (`DependencyHygieneTest`).

Request flow: `YFinance` / `Ticker` / `Tickers` (facade) → `internal/service/` → `internal/http/RawQuoteClient` + `internal/api/` (Feign) → `internal/assembly/` (`FieldSpec` tables in `internal/assembly/specs`, `Resolver`, builders in `internal/assembly/build`) → `instrument` / `detail` records; the chart, options, timeseries, search, lookup and news endpoints go `internal/api/` → `internal/dto/` → `internal/mapper/` → `market` / `fundamentals` / `search` / `news` records.

- **`internal/api/`**: one Feign interface (`@RequestLine`/`@Param`) per Yahoo endpoint. Methods return the **response type directly**: `internal/http/YahooFeign.of(OkHttpClient)` builds the Feign proxies on the library's own OkHttp client (creating its own Jackson 3 mapper) and `target(Class, HttpUrl)` binds one interface — no Feign type appears in `YahooFeign`'s public signature. `YahooFeignClient` maps I/O failures to `YFDataException`; `YahooDecoder` (Jackson 3) turns an empty body or malformed JSON into `YFDataException`; `YahooErrorDecoder` turns non-2xx responses into `YFHttpException` (with `status()`/`path()` and the body) or `YFRateLimitException` (429, with `Retry-After`); `YahooInvocationHandlerFactory` unwraps Feign's `DecodeException` at the proxy boundary so callers only ever see the library's exceptions; all three implement a Feign SPI and are package-private. `http/DependencyHygieneTest` walks every public class outside `internal` and fails if any public/protected member — including generic type arguments and direct supertypes — mentions `tools.jackson.`, `feign.` or an `internal` type; a second test in the same class separately pins that the three SPI implementations above stay package-private. Feign never retries (`Retryer.NEVER_RETRY`) — the OkHttp interceptor chain is the only retry/pacing path — and its `Request.Options` mirror the client's connect/read timeouts and `followRedirects` so `feign-okhttp` uses the client as configured instead of cloning it. `QuoteApi` (`/v7/finance/quote`) and `QuoteSummaryApi` (`/v10/finance/quoteSummary`) return Jackson `JsonNode`, because the assembler resolves wire paths itself; the other endpoints return DTOs. `YahooApis` bundles the interfaces. Fundamentals timeseries uses the **query2** host and the news stream the **finance.yahoo.com** site (`EndpointConfig.financeBase`); everything else uses query1. `NewsApi` (`POST /xhr/ncp?queryRef=…&serviceKey=ncp_fin`) is the only endpoint with a request body: Feign's unannotated parameter (`internal/dto/news/NewsRequest`) is encoded by the `Jackson3Encoder` `YahooFeign` installs on the same mapper as the decoder.
- **`internal/http/RawQuoteClient`**: `quoteRows(symbols)` fetches v7 rows in chunks of **100 distinct symbols** (verified in the survey) and returns them keyed by `Symbol` (absent = Yahoo does not know it); `modules(symbol, moduleNames)` fetches one symbol's quoteSummary modules, `Optional.empty()` when Yahoo has no result for it (a 404 or a 200 with `result: null` — not distinguished).
- **`internal/assembly/`**: the design's "assembly table". `FieldSpec(name, kind, cluster, paths, unit)` is one appendix row; `WirePath` is `v7:field` or `qs:module.path` (an `|UNIT` suffix overrides the unit for that source only, e.g. `v7:dividendYield|PERCENT`). `Kind` is `REQUIRED`/`OPTIONAL`/`LIST`; a cluster name groups `OPTIONAL` specs (present only if every member is) or `REQUIRED` ones (fail together). `Resolver.resolve(Payload, specs)` walks the paths in precedence order — v7 first, then the quoteSummary modules — and yields `Resolved`, whose typed accessors (`decimal/longValue/intValue/string/bool/instant/date/list`, `opt*` variants, `has`, `clusterPresent`, `optCluster(cluster, build)` — applies `build` to `this` only when `clusterPresent(cluster)`, so `build` may read the cluster's members with the plain accessors — `missingRequired`) are what builders read; `JsonValues` (`toLong/toInt/toDecimal`) is the one place both `Resolved` and `internal/assembly/build/Nodes` decode Yahoo's "number or numeric string" convention. `specs/`: `CoreSpecs`, `SessionSpecs`, `BookSpecs`, `PostMarketSpecs`, one `XSpecs` per class, `XDetailSpecs` per detail class, `SnapshotSpecs.forClass/fallbackModules`, `DetailSpecs.forClass/modules`. `build/`: `CoreBuilder`, `TierBuilders`, one builder per record, `RowMappers` for the detail lists, `Nodes` for raw-node helpers. Units (`Unit`: `RAW`, `PERCENT` → ÷100, `EPOCH_SECONDS`/`EPOCH_MILLIS` → `Instant`, `EPOCH_DATE`/`ISO_DATE` → `LocalDate`) are applied by the resolver, never by a builder.
- **`instrument/`**: the sealed snapshot hierarchy — `Instrument` permits `Equity`, `Etf`, `MutualFund`, `Index`, `Crypto`, `FxPair`, `Future`, `Unclassified`; tier interfaces `IntradayTraded` (`session()`), `Quoted` (`Optional<TopOfBook> book()`), `Fund` (`ytdReturn()`, `threeMonthReturn()`); value records `Core`, `Session`, `TopOfBook`, `PostMarket`, `TrailingDividend`, `EquityLikeStats`, `QuoteCurrency(code, Optional<Currency> iso)`, enums `AssetClass` (`fromQuoteType`), `MarketState`. **`detail/`**: `EquityDetail`, `EtfDetail`, `MutualFundDetail` (the last two implement `FundDetail`, which holds the shared nested records), `CryptoDetail`; `detail/rows` holds the list-row records.
- **`batch/`**: `Batch<T>` (input-ordered `List<Outcome<T>>`, `Iterable<Outcome<T>>`; `values/ok/skipped/failed/get/summary`, `stream()`, `allOk()`, `toMap()` — `Ok` values by symbol, insertion-ordered, first wins —, `orElseThrowAll()` — throws the first non-`Ok` outcome's exception —, `map(fn)` — retypes `Ok`, passes `Skipped`/`Failed` through), sealed `Outcome<T>` = `Ok` | `Skipped(reason, detail)` | `Failed(error)` (`optional()`, `map(fn)`, `orElseThrow()` — `Skipped` throws `YFSkippedException`, a `YFMissingDataException` carrying `reason()`/`symbol()`), `SkipReason`, and — in `internal/batch`, not exported — `FanOut.run(symbols, concurrency, perSymbol)` — virtual threads plus a `Semaphore`, results in input order, an exception from the worker becomes `Failed` (an `Error` is rethrown), each worker starts with a copy of the caller's MDC and clears it when done. `Skipped` is never retryable; `Failed.isRetryable()` delegates to `YFinanceException.isRetryable()` (see the exception rule below); keep that distinction when adding outcomes.
- **`internal/service/`**: `InstrumentService` (classify by `quoteType` → resolve the class's snapshot specs against the v7 row → if a required field is short, one quoteSummary request with `SnapshotSpecs.fallbackModules(class)` → build, or downgrade to `Unclassified`; a symbol absent from v7 or with an incomplete core is `Skipped(UNKNOWN_SYMBOL)`; `instruments(symbols, Class)` narrows to `Skipped(WRONG_ASSET_CLASS | DOWNGRADED)`), `DetailService` (one quoteSummary request per instrument with `DetailSpecs.modules(class)`, fanned out through `FanOut` with the concurrency passed at construction — `YFinance.create(config)` passes `EndpointConfig.fanOutConcurrency()`, default `Tickers.DEFAULT_CONCURRENCY`, which also seeds every `Tickers`; a missing required field is `Skipped(MODULE_ABSENT, "a,b")`), `HistoryService`, `FundamentalsService` (takes the `Equity` proof; `getStatements(equity, Set<StatementType>, Set<Frequency>)` joins every servable pair's prefixed keys and fetches them in as few timeseries requests as the key count allows (≤ 150 keys each, `MAX_KEYS_PER_REQUEST`; one per statement in practice) and splits the merged response with the key-filtering `FundamentalsMapper.toStatement(response, type, frequency, keys)` overload — `TRAILING`×`BALANCE_SHEET` is skipped, an empty set or that pair alone is an `IllegalArgumentException`; `requireServablePairs(types, frequencies)` is that check, and `YFinance`'s two batch `statements` forms call it before fanning out so a bad argument is one exception, not N `Failed`; a failed chunk fails the whole call, never a partial statement; `getSharesOutstanding(equity, start, end)` (batch E/1, `get_shares_full` parity) calls the second `FundamentalsApi` method (`type=shares_out`, plain-long series, its own `internal/dto/timeseries/SharesResponse` shape) and maps with `internal/mapper/SharesMapper.toList` — tolerant of absence (empty list, not an exception) since Yahoo answers that for non-equities and unknown data; `start >= end` is an `IllegalArgumentException`; `getValuationHistory(equity, Frequency)` (batch E/2, `Ticker.valuation` parity) requests the nine `internal/mapper/ValuationMapper.KEYS` with the frequency prefix through the same `fetchSeries` as statements — one request — and `ValuationMapper.toList` groups the points by `asOfDate` into `fundamentals.ValuationMeasures` rows, oldest first, every measure `Optional`, `currency` from the market-cap or enterprise-value point; `QUARTERLY` is the latest five quarter ends and `ANNUAL` the latest four fiscal year ends (live-probed 2026-10-01: Yahoo holds about six quarters and returns the latest five inside the window, so an earlier `period2` reaches at most one more — not worth a window parameter), `TRAILING` is an `IllegalArgumentException` because Yahoo's trailing series is an irregular set of per-measure snapshot dates; results without series (a non-equity, an unknown symbol) are an empty list), `OptionsService`, `SearchService`, `LookupService`, `NewsService` (`getNews(symbol, NewsTab, count)`, `Ticker.news`/`get_news` parity: one POST, `internal/mapper/NewsMapper.toItems` keeps Yahoo's order, filters entries with a non-empty `ad`, drops an item missing `id`/`title`/`pubDate`/`canonicalUrl`/`provider.displayName` — the keys present on 60 of 60 surveyed items — and answers a missing stream, e.g. an unknown symbol, with an empty list; `count < 1` is an `IllegalArgumentException`). Services return `Outcome`/`Batch`; `Ticker` calls `orElseThrow()`. `HistoryService.getHistory(Symbol, HistoryQuery)` (`market.HistoryQuery`) is the implementation `Ticker.history(HistoryQuery)`/`Tickers.histories(HistoryQuery)`/`YFinance.histories(Collection<Symbol>, HistoryQuery)` call — the only price-history query type.
- **`internal/http/`**: `YahooClientFactory` builds two OkHttp clients that share one cookie jar, one `AdaptiveRateLimitInterceptor` (`newRateLimiter(config)`: clamps `maxDelay` to `callTimeout` when longer, one WARN — the `EndpointConfig` record itself never rejects a tuning, so withers work in any order), one `Dispatcher` (`newDispatcher(config)`: `maxRequests = maxRequestsPerHost = max(fanOutConcurrency, 5)` — OkHttp applies these only to `enqueue`d calls, and every library call is synchronous, so this is for callers who `enqueue` through the customizer's client; the fan-out semaphore is the library's own bound) and one `ConnectionPool`. `YFinance.create` builds those pieces and passes them to the 5-/7-arg overloads; the shorter overloads build them privately. `YFinance.close()` shuts down only the dispatcher/pool it created (identity check) — one installed by the customizer is the caller's.
  - `baseClient` handles the auth handshake. It has no crumb interceptor, which avoids recursion, but carries the shared limiter (LogContext → AdaptiveRateLimit → RequestLog) so the handshake is paced like any data request. A handshake triggered from inside a paced api request (same thread) is recognised through a thread-local flag in `AdaptiveRateLimitInterceptor` and skips the wait — it rides in the slot the api request already paid for — while its responses still feed the limiter.
  - `apiClient` runs the interceptor chain UserAgent → LogContext → AuthRetry → TransientErrorRetry (5xx, `RetryConfig`) → AdaptiveRateLimit → RequestLog → Crumb. Anything that re-issues a request sits upstream of the rate limiter so retries are paced.
  - `AdaptiveRateLimiter` retries 429s up to `maxAttempts` and paces **every** request while degraded. `pendingWait()` returns the wait (reserving the slot when zero); `onResponse(code, retryAfter, sentNanos)` raises the pace once per burst — a 429 for a request sent before the last increase only defers the next slot, unless the pace has meanwhile recovered to zero (then it is a new event). It takes an injected clock and sleeper for tests; `nanoTime()` exposes the clock so the interceptor measures elapsed time on it.
  - **Call budget:** every wait an interceptor imposes (pacing, 5xx backoff) is checked by `CallBudget.fits` against `chain.call().timeout().timeoutNanos()` minus the time since the interceptor was entered — OkHttp's call timeout only cancels, it never wakes a sleeping interceptor. Pacing fails fast with `RateLimitBudgetExceeded` (an `InterruptedIOException` carrying the pending wait), which `YahooFeignClient` maps to `YFRateLimitException("Rate-limit pacing of N ms exceeds the remaining call timeout for <path>", retryAfter = wait)`; the 5xx backoff fails with a plain `InterruptedIOException("retry wait of N ms …")` → `YFDataException`. Both sleep in ≤ 1 s slices (`CallBudget.SLICE`) and stop with `"Canceled"` when the call is cancelled. `AdaptiveRateLimitConfig.defaults().maxDelay()` is 10 s; a longer cap is clamped at client creation, never rejected.
  - `AuthRetryInterceptor` reads the rejected crumb off the sent request (`response.request().url().queryParameter("crumb")`). `onRejectedCrumb(consumer, crumbSupplier)` hands it to the hook and skips the retry when the request carried no crumb and the supplier still yields none (a cooldown); there is no public constructor and no unconditional form. Pair it with `CrumbStore.invalidate(rejected)` — the store has no unconditional `invalidate()` either — so a burst of 401s costs one handshake.
  - `YahooDecoder` reads the body once: a body whose first non-whitespace byte is `<` is a `YFAuthException` ("HTML page instead of JSON … consent required or access blocked") before Jackson runs — the body sniff decides, never the `Content-Type` alone; the bytes are handed to Jackson as a repeatable body.
  - `RawQuoteClient.quoteRows` is the one-request primitive for ≤ `CHUNK` (100) distinct symbols and rejects more; `InstrumentService` chunks, isolates a failed chunk (its symbols are `Failed`, the rest proceed) and fans the quoteSummary fallbacks out through `FanOut` with the constructor's concurrency, logging `fallbacks=N` in the batch summary.
  - All tuning lives in the immutable `EndpointConfig` / `AdaptiveRateLimitConfig` / `RetryConfig` records, every field with a wither. Build configs as `EndpointConfig.production().with...()` (`withHosts(base)` for tests — it points all four hosts, `query1Base`/`query2Base`/`financeBase`/`cookieUrl`, at `base`); the canonical constructor is the only one — no convenience or legacy overloads. `EndpointConfig.cookieJar()` (a fresh `InMemoryCookieJar` per `production()`; must be thread-safe, shared by every `YFinance` created from that config instance) and `clock()` (`Clock.systemUTC()`) are components: `YFinance.create` hands the jar to both OkHttp clients and the clock to `InstrumentService`/`DetailService`/`HistoryService`/`FundamentalsService`; `fromApis` uses the system clock.
- **`internal/auth/CrumbStore`**: gets a cookie from `fc.yahoo.com`, then a crumb from `/v1/test/getcrumb`, and caches it until invalidated. `invalidate(rejected)` clears only if the cache still holds that crumb. Any failed handshake starts a cooldown — `max(Retry-After, 30 s doubling to 5 min)`, reset by a success — during which `tryGetCrumb()` returns empty with no network call (WARN once on entering, DEBUG after): a transient failure (429 or I/O) is swallowed by `tryGetCrumb()` on the call that meets it, a rejection (403, blank or HTML crumb) still throws `YFAuthException` from that call. `getCrumb()` always attempts. The monotonic clock is injectable (package-private constructor).
- **`internal/http/YahooJsonMapper` + `RawAwareNumberModule`**: `YahooJsonMapper.create()` builds the Jackson 3 `JsonMapper` used to decode Yahoo's JSON (java.time support is built in, so no separate date/time module is needed, and unknown properties/enum values are tolerated). quoteSummary returns some numbers as `{raw, fmt}` objects even with `formatted=false`; `RawAwareNumberModule` unwraps them globally for DTOs, and `Payload` and `Nodes` unwrap `raw` when the assembler reads a `JsonNode`. Don't add per-field workarounds.
- **`enums/`**: closed sets implement `WireEnum` (`wireValue()`). Resolve incoming values with `WireEnum.fromWire(values(), wire, label)`. `LineItem` gives type-safe keys for fundamentals; `FinancialStatement.value(LineItem, date)`/`latest(LineItem)`/`row(LineItem)` throw `IllegalArgumentException` when the item's `statement()` is not the statement's `type()` (the `String`-key form stays lenient).
- **Facade**: `YFinance` batch calls (`instruments`, `equityDetails`/`etfDetails`/`mutualFundDetails`/`cryptoDetails` — separate names because of erasure —, `histories`, `statements` (single-statement and `Set`×`Set` multi-statement forms), `options`) return `Batch<T>`, N in → N out, input order, duplicates preserved, empty input makes no request. `YFinance.detail(Equity|Etf|MutualFund|Crypto)` and `YFinance.statements(Equity, type, frequency)` are the instrument-first single forms (one request each, `orElseThrow()` on the service outcome). `Ticker` returns a value or throws (`as(Class)` → `YFClassMismatchException`; unknown symbol → `YFMissingDataException`); `detail(...)`/`statements(...)` take the instrument as a class proof, check its symbol matches the ticker, then delegate to the `YFinance` forms. `Tickers.fetch(Function<? super Ticker, T>)` fans any `Ticker` call out through `FanOut` (`withConcurrency(n)`) and classifies like the batch calls: a `YFSkippedException` keeps its reason as `Skipped`, a `YFClassMismatchException` becomes `Skipped(WRONG_ASSET_CLASS | DOWNGRADED)`, every other exception is `Failed`; `instruments()` is one batched request; `histories(HistoryQuery)` (`histories(range, interval)` is a shorthand for it) is a `fetch(Ticker::history)`. A fetcher returning `null` becomes `Failed`, never an `Ok` with a null value.
- **`YFinance.fromApis(YahooApis)`** skips the handshake. It is package-private — `YahooApis` is internal — and exists for the facade tests in the root package.

## Conventions

- Use specific types in models: `BigDecimal` for money, `Instant`/`LocalDate`/`ZoneId` for time, `QuoteCurrency` for currencies (raw code plus `Optional<Currency>` — pence codes such as `GBp` are not ISO and must not fail), `java.net.URI` for URLs, and value records such as `valueobject/Symbol`. Model types are records; collections in them are immutable (`List.copyOf` in the compact constructor).
- **No `@Nullable` in the public model** (`instrument`, `detail`, `batch`, `market`, `fundamentals`, `search`, `news`). Absence is one of: the field does not exist on that class; a non-null component whose absence downgrades the instrument to `Unclassified` (snapshot) or skips the detail (`MODULE_ABSENT`); `Optional<T>`, clustered into a record when absences co-occur. Lists are never `Optional` — empty when Yahoo omits the module. Never coerce a missing value to a default. `@Nullable` remains normal everywhere under `internal/`.
- **The appendix is normative.** Required fields are exactly the `R` rows of Appendix A (Intrinsic rule, design D5); `AppendixConformanceTest` parses the appendix tables and asserts every in-code `FieldSpec` list has the same names, kinds, clusters and wire-path precedence. To add or change a field: edit the appendix row (name, kind, sources in precedence order, unit note) → add/adjust the `FieldSpec` in the class's `XSpecs` → read it in the builder with the matching `Resolved` accessor (`decimal` for `R`, `optDecimal` for `O`, `optCluster(cluster, build)` for a cluster) and add the record component → cover it with a fixture-backed builder/service test → `AppendixConformanceTest` green. Promoting or demoting a kind without the appendix change is a bug even if the code compiles. Precedence is `v7`, then `price`, `summaryDetail`, `quoteType`, `defaultKeyStatistics`, then class modules.
- **Units** live in the spec, not the builder: fields Yahoo serves as percents (v7 `changePercent`/`postMarketChangePercent` — the `price` module already serves fractions — v7 `dividendYield`, v7 `netExpenseRatio`/`ytdReturn`/`trailingThreeMonthReturns`/`trailingThreeMonthNavReturns`, `debtToEquity`, `fiveYearAvgDividendYield`, options `percentChange`) are `PERCENT` → stored as fractions; every other yield, margin and held-percent is already a fraction; epoch seconds/millis → `Instant`, date-only epochs → `LocalDate` (UTC). Verify a new percent field against a fixture pair (v7 vs quoteSummary) before choosing the unit.
- **Snapshot fallback modules are derived, not listed:** `SnapshotSpecs.fallbackModules(class)` is `price,summaryDetail,quoteType` plus every quoteSummary module the class's own snapshot specs reference — add a wire path and the fallback request follows (the first live drift run caught the fixed three-module list downgrading every UCITS ETF). `DetailSpecs.modules(class)` is a fixed per-class list; when a detail spec gains a path into a module not yet in that list, add the module there too, and assert the module list in a test.
- **Drop and log at DEBUG:** a datum that cannot be mapped is dropped, never defaulted and never fatal — a bar missing any OHLC value, an option contract missing a 100 %-survey field, a detail list row missing its identifier (`RowMappers`), a news item missing a 100 %-survey field (`NewsMapper`), a downgrade (`InstrumentService`, with the `missing` list as a key-value). Structural breakage that leaves nothing sensible to return (incomplete chart metadata, a promised option chain with no `options` bucket) throws `YFDataException`.
- `MapperSupport` holds the shared helpers for the DTO mappers (`epochSecond`, `uri`, `zoneId`, `localDate`, `firstResult`). Reuse them; `internal/assembly/build/Nodes` is the equivalent for `JsonNode` builders.
- **Testing is fixture-first and never touches the network.** Fixtures are real captures in `src/test/resources/fixtures/` (`instruments/v7_<SYM>.json` + `qs_<SYM>.json` per surveyed symbol — AAPL, PLUG, 005930.KS, BAC-PL, TTE.PA, 1299.HK (no postal code), SPY, GLD, CSPX.L, VFIAX, ^GSPC, BTC-USD, EURUSD=X, ES=F, RIDE — plus `options/`, one chart, `timeseries_income_annual.json`/`timeseries_multi.json` (+ the chunk-merge test's own `timeseries_multi_chunk1.json`/`_chunk2.json`), `timeseries_shares_out_aapl.json`, `timeseries_valuation_quarterly_<sym>.json` (AAPL, TTE.PA with per-measure gaps, 005930.KS, SPY and an unknown symbol with no series) + `timeseries_valuation_annual_aapl.json`, `news/ncp_<tab>_<SYM>.json` (AAPL on all three tabs, SPY/BTC-USD/TTE.PA on the news tab, `ncp_news_unknown.json` for a symbol Yahoo has no stream for), search, lookup), refreshed by the `Capture*Fixtures` live tests (`CAPTURE_SYMBOLS=1299.HK` limits `CaptureInstrumentFixtures` to the named symbols — refreshing all of them rewrites the values many tests assert on). `testsupport/InstrumentFixtures` loads a symbol's v7 row / quoteSummary modules / `Payload` for builder tests; `testsupport/YahooDispatcher` routes every endpoint of a `MockWebServer` to those captures so a whole `YFinance.fromApis(...)` runs over real payloads (`YahooDispatcher.UNKNOWN` is a symbol no capture knows); `testsupport/Instruments` builds proof instruments (`Instruments.equity("AAPL")`); `testsupport/Fixtures` is the low-level `jsonResponse`/`api` pair for single-endpoint tests. A new field or endpoint needs a fixture, a failing test, then the implementation; assert request counts when the change touches the fallback.
- **Live suite and drift detector** (`src/integrationTest`, `@Tag("live")`, weekly via `live.yml`): `LiveYahooIntegrationTest` exercises every facade call through the real client; `GuaranteeDriftTest` classifies the 282-symbol survey list in one batch and fails, naming the missing field, if more than `max(1, 1 %)` of a class's live instruments downgrade. Never probe Yahoo with raw `curl`; captures go through `YahooClientFactory.apiClient(EndpointConfig.production())` in a live test.
- All errors are `YFinanceException` subtypes: `YFDataException` (→ `YFHttpException`, `YFMissingDataException` → `YFSkippedException`, `YFClassMismatchException`), `YFRateLimitException`, `YFAuthException`. Batches wrap them in `Outcome.Failed`; `Skipped` is for "Yahoo answered, nothing to return". `isRetryable()`: base `false`; `YFRateLimitException` `true`; `YFHttpException` `status >= 500`; `YFDataException` when its direct cause is an `IOException`; `YFMissingData`/`YFSkipped`/`YFClassMismatch`/`YFAuth` `false` — the README error table's last column must match.
- **Nullness tooling:** every package is JSpecify `@NullMarked` (see each `package-info.java`). Unannotated = never null; DTO components are all `@Nullable` by design. Record accessors inherit component nullness, so a component normalised in a compact constructor (lists) stays non-null in its declaration. Prefer restructuring code (locals, a small helper) over `@SuppressWarnings("NullAway")`.
- **Runtime nullness guards are for invariants, not a substitute for NullAway.** For public records, `@NullMarked` + NullAway *is* the non-null contract; NullAway already rejects a null argument at every call site NullAway can see, so a blanket `requireNonNull` per component adds nothing and only earns its keep when a genuine invariant needs to read the component (mutual exclusion, ordering, an immutable copy of a mutable collection, a factory's normalisation). Most of the ~70 public records in `instrument`/`detail`/`batch`/`market`/`fundamentals`/`search` have no compact-constructor guards at all, on purpose. The three that do: `instrument/QuoteCurrency` (`requireNonNull` on `code`/`iso`: the one model record built from a raw wire string through a normalising factory, `of(String)`), `batch/Outcome`'s sealed variants (`Ok`/`Skipped`/`Failed` each guard the components their own factory logic reads), and `market/HistoryQuery` (guards `interval`/`range`/`start`/`end`/`events` because the constructor then checks the range/period mutual-exclusion invariant and copies `events` into an immutable set — the guards exist to make those reads safe, not as a blanket policy). Do not add a `requireNonNull` to a component a compact constructor never reads.
- **Logging:** SLF4J (`LoggerFactory.getLogger(X.class)`); `slf4j-api` is an `api` dependency and the only logging dependency — never add a backend to main. Tests bind Logback at WARN (`src/test/resources/logback-test.xml`) — not slf4j-simple, whose MDC is a no-op. Use the fluent API (`LOG.atWarn().log(...)`, `LOG.atLevel(level)...`); `{}` placeholders, never concatenation. **Context:** every service entry point wraps its work in `LogContext.scope(op, symbol)` (MDC keys `yf.op`, `yf.symbol` — for a batch the first five symbols then `,…+N`; the `LogContextInterceptor` adds `yf.endpoint` per HTTP call; `FanOut` workers inherit the caller's MDC). The `op` names are `instruments`, `details`, `history`, `statements`, `shares`, `valuation`, `options`, `search`, `lookup`, `news`, `fetch`; add a new one only for a genuinely new operation. MDC is thread-local, so anything that runs on a `FanOut` worker opens its per-symbol scope **on the worker** (see `DetailService.one`, `Tickers.fetchOne`), not only around the batch. Event facts (`status`, `attempt`, `delayMs`, `reason`, `cause`, `missing`) go as `addKeyValue(...)`, not into MDC. **Level discipline:** `WARN` only for degraded-or-gave-up (empty in a healthy run); `INFO` once per client lifetime or per multi-symbol batch (`batch.summary()`), never per symbol — the services log a one-symbol batch's summary at `DEBUG`, since `Ticker.instrument()`/`detail(...)` go through them; `DEBUG` once per request (`RequestLogInterceptor`), per downgrade or per dropped datum. Never log an exception the library also throws. Assert log output in tests with `testsupport.LogCapture`.
- **Compatibility:** the library has no consumers yet, so there are no deprecation cycles or compatibility shims — change or remove API outright and say so in the PR body.
- **HTTP client:** `EndpointConfig.clientCustomizer` must be applied last in `YahooClientFactory` so users can override anything the library sets.
