# AGENTS.md

Guidance for AI coding agents working in this repository.

## Project

`yfinance-java`: a Java 21 port of the Python [`yfinance`](https://github.com/ranaroussi/yfinance) library, built on OpenFeign 13 / OkHttp 5 / Jackson 3 with Gradle 9 (Kotlin DSL, version catalog in `gradle/libs.versions.toml`). It is a plain library with no framework dependencies. The package root is `io.github.dimazigel.yfinance`, and it publishes as `io.github.dimazigel:yfinance-java` (GitHub Packages only — Maven Central was considered and declined; see `RELEASING.md`). The public API is described in `README.md`; the field-level contract of the model is `docs/superpowers/specs/2026-09-26-typed-instrument-model-appendix.md` (Appendix A, normative), explained by `…-design.md` and backed by `…-yahoo-field-survey.md`.

## Commands

```bash
./gradlew test                    # unit tests (excludes @Tag("live")) + JaCoCo report
./gradlew test --tests 'io.github.dimazigel.yfinance.service.InstrumentServiceTest'             # one class
./gradlew test --tests 'io.github.dimazigel.yfinance.assembly.build.EquityBuilderTest.samsungLacksBookValueButIsStillAnEquity'  # one method
./gradlew integrationTest         # opt-in live suite against real Yahoo (src/integrationTest, @Tag("live"))
./gradlew build                   # compile (+Error Prone/NullAway/-Werror) + tests + Spotless check + coverage floor + jars; what CI runs
./gradlew spotlessApply           # fix import order / whitespace before committing
./gradlew publishToMavenLocal     # install 0.1.0-SNAPSHOT for consuming projects
```

Main code compiles with **Error Prone's default checks + NullAway + `-Werror`**, so any finding fails `compileJava`; test code is compiled without Error Prone. **Spotless** pins import order (static first, then one lexicographic block), unused imports, trailing whitespace and final newlines — `./gradlew spotlessApply` fixes, `check` verifies; indentation/wrapping are not enforced, match the surrounding code. `check` also enforces a **JaCoCo floor** of 85 % line / 60 % branch. Dependency scopes: `api` only for types in the public API (OkHttp, JSpecify, slf4j-api); Feign and Jackson are both `implementation` — don't put their types in public signatures (the `@RequestLine`/`@Param` annotations on the `api/` interfaces are the only Feign symbols visible to consumers). Jackson 3 splits its packages: databind and core types live under `tools.jackson.*`, while annotations stay on `com.fasterxml.jackson.annotation` (Jackson 3 keeps that package), so DTO annotations are untouched. The jar carries `Automatic-Module-Name: io.github.dimazigel.yfinance`. Configuration cache, parallel builds and build caching are enabled in `gradle.properties`, so custom Gradle tasks must stay configuration-cache compatible (see `VerifySourcesPublicationTask` in `build.gradle.kts`). Releases are cut by manually running the **Release** workflow (`.github/workflows/release.yml`) on `main`. It bumps the latest tag (patch/minor/major) or takes an explicit version, builds and tests, publishes to GitHub Packages, then creates the tag and GitHub release. Tags have no `v` prefix (`0.0.2`). `publish.yml` still publishes releases created by hand in the GitHub UI, skipping releases authored by `github-actions[bot]`. Both workflows run `.github/scripts/check-published.sh` first and skip publishing if the version already exists in GitHub Packages, so re-running a half-failed release is safe and nothing is ever uploaded twice. `live.yml` runs the live integration suite weekly (and on demand) to detect Yahoo API drift. Both workflows pass the version to Gradle as `-PreleaseVersion` and publish with the explicit `publishAllPublicationsToGitHubPackagesRepository` task. Plain `maven-publish`; the publication is named `mavenJava`.

## Architecture

Request flow: `YFinance` / `Ticker` / `Tickers` (facade) → `service/` → `http/RawQuoteClient` + `api/` (Feign) → `assembly/` (`FieldSpec` tables in `assembly/specs`, `Resolver`, builders in `assembly/build`) → `instrument` / `detail` records; the chart, options, timeseries, search and lookup endpoints go `api/` → `dto/` → `mapper/` → `market` / `fundamentals` / `search` records.

- **`api/`**: one Feign interface (`@RequestLine`/`@Param`) per Yahoo endpoint. Methods return the **response type directly**: `http/YahooFeign.builder(OkHttpClient, JsonMapper)` builds the Feign proxies on the library's own OkHttp client — `YahooFeignClient` maps I/O failures to `YFDataException`; `YahooDecoder` (Jackson 3) turns an empty body or malformed JSON into `YFDataException`; `YahooErrorDecoder` turns non-2xx responses into `YFHttpException` (with `status()`/`path()` and the body) or `YFRateLimitException` (429, with `Retry-After`); `YahooInvocationHandlerFactory` unwraps Feign's `DecodeException` at the proxy boundary so callers only ever see the library's exceptions. Feign never retries (`Retryer.NEVER_RETRY`) — the OkHttp interceptor chain is the only retry/pacing path — and its `Request.Options` mirror the client's connect/read timeouts and `followRedirects` so `feign-okhttp` uses the client as configured instead of cloning it. `QuoteApi` (`/v7/finance/quote`) and `QuoteSummaryApi` (`/v10/finance/quoteSummary`) return Jackson `JsonNode`, because the assembler resolves wire paths itself; the other endpoints return DTOs. `YahooApis` bundles the interfaces. Fundamentals timeseries uses the **query2** host; everything else uses query1.
- **`http/RawQuoteClient`**: `quoteRows(symbols)` fetches v7 rows in chunks of **100 distinct symbols** (verified in the survey) and returns them keyed by `Symbol` (absent = Yahoo does not know it); `modules(symbol, moduleNames)` fetches one symbol's quoteSummary modules, `Optional.empty()` when Yahoo has no result for it (a 404 or a 200 with `result: null` — not distinguished).
- **`assembly/`**: the design's "assembly table". `FieldSpec(name, kind, cluster, paths, unit)` is one appendix row; `WirePath` is `v7:field` or `qs:module.path` (an `|UNIT` suffix overrides the unit for that source only, e.g. `v7:dividendYield|PERCENT`). `Kind` is `REQUIRED`/`OPTIONAL`/`LIST`; a cluster name groups `OPTIONAL` specs (present only if every member is) or `REQUIRED` ones (fail together). `Resolver.resolve(Payload, specs)` walks the paths in precedence order — v7 first, then the quoteSummary modules — and yields `Resolved`, whose typed accessors (`decimal/longValue/intValue/string/bool/instant/date/list`, `opt*` variants, `has`, `clusterPresent`, `missingRequired`) are what builders read. `specs/`: `CoreSpecs`, `SessionSpecs`, `BookSpecs`, `PostMarketSpecs`, one `XSpecs` per class, `XDetailSpecs` per detail class, `SnapshotSpecs.forClass/fallbackModules`, `DetailSpecs.forClass/modules`. `build/`: `CoreBuilder`, `TierBuilders`, one builder per record, `RowMappers` for the detail lists, `Nodes` for raw-node helpers. Units (`Unit`: `RAW`, `PERCENT` → ÷100, `EPOCH_SECONDS`/`EPOCH_MILLIS` → `Instant`, `EPOCH_DATE`/`ISO_DATE` → `LocalDate`) are applied by the resolver, never by a builder.
- **`instrument/`**: the sealed snapshot hierarchy — `Instrument` permits `Equity`, `Etf`, `MutualFund`, `Index`, `Crypto`, `FxPair`, `Future`, `Unclassified`; tier interfaces `IntradayTraded` (`session()`), `Quoted` (`Optional<TopOfBook> book()`), `Fund` (`ytdReturn()`, `threeMonthReturn()`); value records `Core`, `Session`, `TopOfBook`, `PostMarket`, `TrailingDividend`, `EquityLikeStats`, `QuoteCurrency(code, Optional<Currency> iso)`, enums `AssetClass` (`fromQuoteType`), `MarketState`. **`detail/`**: `EquityDetail`, `EtfDetail`, `MutualFundDetail` (the last two implement `FundDetail`, which holds the shared nested records), `CryptoDetail`; `detail/rows` holds the list-row records.
- **`batch/`**: `Batch<T>` (input-ordered `List<Outcome<T>>`; `values/skipped/failed/get/summary`), sealed `Outcome<T>` = `Ok` | `Skipped(reason, detail)` | `Failed(error)` (`optional()`, `orElseThrow()` — `Skipped` throws `YFSkippedException`, a `YFMissingDataException` carrying `reason()`/`symbol()`), `SkipReason`, and `FanOut.run(symbols, concurrency, perSymbol)` — virtual threads plus a `Semaphore`, results in input order, an exception from the worker becomes `Failed`. `Skipped` is non-retryable, `Failed` retryable; keep that distinction when adding outcomes.
- **`service/`**: `InstrumentService` (classify by `quoteType` → resolve the class's snapshot specs against the v7 row → if a required field is short, one quoteSummary request with `SnapshotSpecs.fallbackModules(class)` → build, or downgrade to `Unclassified`; a symbol absent from v7 or with an incomplete core is `Skipped(UNKNOWN_SYMBOL)`; `instruments(symbols, Class)` narrows to `Skipped(WRONG_ASSET_CLASS | DOWNGRADED)`), `DetailService` (one quoteSummary request per instrument with `DetailSpecs.modules(class)`, fanned out through `FanOut` with the concurrency passed at construction — `YFinance.create(config)` passes `EndpointConfig.fanOutConcurrency()`, default `Tickers.DEFAULT_CONCURRENCY`, which also seeds every `Tickers`; a missing required field is `Skipped(MODULE_ABSENT, "a,b")`), `HistoryService`, `FundamentalsService` (takes the `Equity` proof), `OptionsService`, `SearchService`, `LookupService`. Services return `Outcome`/`Batch`; `Ticker` calls `orElseThrow()`.
- **`http/`**: `YahooClientFactory` builds two OkHttp clients that share one cookie jar:
  - `baseClient` handles the auth handshake. It has no crumb interceptor, which avoids recursion.
  - `apiClient` runs the interceptor chain UserAgent → AuthRetry → TransientErrorRetry (5xx, `RetryConfig`) → AdaptiveRateLimit → Crumb. Anything that re-issues a request sits upstream of the rate limiter so retries are paced.
  - `AdaptiveRateLimiter` retries 429s up to `maxAttempts` and paces **every** request while degraded. It takes an injected clock and sleeper for tests.
  - `AuthRetryInterceptor` invalidates the crumb on 401/403 and retries once.
  - All tuning lives in the immutable `EndpointConfig` / `AdaptiveRateLimitConfig` records. Build configs as `EndpointConfig.production().with...()` (`withHosts(base)` for tests); there are no convenience constructors.
- **`auth/CrumbStore`**: gets a cookie from `fc.yahoo.com`, then a crumb from `/v1/test/getcrumb`, and caches it until invalidated.
- **`http/YahooJsonMapper` + `RawAwareNumberModule`**: `YahooJsonMapper.create()` builds the Jackson 3 `JsonMapper` used to decode Yahoo's JSON (java.time support is built in, so no separate date/time module is needed, and unknown properties/enum values are tolerated). quoteSummary returns some numbers as `{raw, fmt}` objects even with `formatted=false`; `RawAwareNumberModule` unwraps them globally for DTOs, and `Payload` and `Nodes` unwrap `raw` when the assembler reads a `JsonNode`. Don't add per-field workarounds.
- **`enums/`**: closed sets implement `WireEnum` (`wireValue()`). Resolve incoming values with `WireEnum.fromWire(values(), wire, label)`. `LineItem` gives type-safe keys for fundamentals.
- **Facade**: `YFinance` batch calls (`instruments`, `equityDetails`/`etfDetails`/`mutualFundDetails`/`cryptoDetails` — separate names because of erasure —, `histories`, `statements`, `options`) return `Batch<T>`, N in → N out, input order, duplicates preserved, empty input makes no request. `Ticker` returns a value or throws (`as(Class)` → `YFClassMismatchException`; unknown symbol → `YFMissingDataException`); `detail(...)`/`statements(...)` take the instrument as a class proof and check its symbol matches the ticker. `Tickers.fetch(Function<? super Ticker, T>)` fans any `Ticker` call out through `FanOut` (`withConcurrency(n)`) and classifies like the batch calls: a `YFSkippedException` keeps its reason as `Skipped`, a `YFClassMismatchException` becomes `Skipped(WRONG_ASSET_CLASS | DOWNGRADED)`, every other exception is `Failed`; `instruments()` is one batched request; `histories(range, interval)` is a shorthand. A fetcher returning `null` becomes `Failed`, never an `Ok` with a null value.
- **`YFinance.fromApis(YahooApis)`** skips the handshake. Use it for tests and advanced wiring.

## Conventions

- Use specific types in models: `BigDecimal` for money, `Instant`/`LocalDate`/`ZoneId` for time, `QuoteCurrency` for currencies (raw code plus `Optional<Currency>` — pence codes such as `GBp` are not ISO and must not fail), `java.net.URI` for URLs, and value records such as `valueobject/Symbol`. Model types are records; collections in them are immutable (`List.copyOf` in the compact constructor).
- **No `@Nullable` in the public model** (`instrument`, `detail`, `batch`, `market`, `fundamentals`, `search`). Absence is one of: the field does not exist on that class; a non-null component whose absence downgrades the instrument to `Unclassified` (snapshot) or skips the detail (`MODULE_ABSENT`); `Optional<T>`, clustered into a record when absences co-occur. Lists are never `Optional` — empty when Yahoo omits the module. Never coerce a missing value to a default. `@Nullable` remains normal in `dto/`, `mapper/`, `assembly/` internals and `http/`.
- **The appendix is normative.** Required fields are exactly the `R` rows of Appendix A (Intrinsic rule, design D5); `AppendixConformanceTest` parses the appendix tables and asserts every in-code `FieldSpec` list has the same names, kinds, clusters and wire-path precedence. To add or change a field: edit the appendix row (name, kind, sources in precedence order, unit note) → add/adjust the `FieldSpec` in the class's `XSpecs` → read it in the builder with the matching `Resolved` accessor (`decimal` for `R`, `optDecimal` for `O`, `clusterPresent` + plain accessors for a cluster) and add the record component → cover it with a fixture-backed builder/service test → `AppendixConformanceTest` green. Promoting or demoting a kind without the appendix change is a bug even if the code compiles. Precedence is `v7`, then `price`, `summaryDetail`, `quoteType`, `defaultKeyStatistics`, then class modules.
- **Units** live in the spec, not the builder: fields Yahoo serves as percents (v7 `changePercent`/`postMarketChangePercent` — the `price` module already serves fractions — v7 `dividendYield`, v7 `netExpenseRatio`/`ytdReturn`/`trailingThreeMonthReturns`/`trailingThreeMonthNavReturns`, `debtToEquity`, `fiveYearAvgDividendYield`, options `percentChange`) are `PERCENT` → stored as fractions; every other yield, margin and held-percent is already a fraction; epoch seconds/millis → `Instant`, date-only epochs → `LocalDate` (UTC). Verify a new percent field against a fixture pair (v7 vs quoteSummary) before choosing the unit.
- **Snapshot fallback modules are derived, not listed:** `SnapshotSpecs.fallbackModules(class)` is `price,summaryDetail,quoteType` plus every quoteSummary module the class's own snapshot specs reference — add a wire path and the fallback request follows (the first live drift run caught the fixed three-module list downgrading every UCITS ETF). `DetailSpecs.modules(class)` is a fixed per-class list; when a detail spec gains a path into a module not yet in that list, add the module there too, and assert the module list in a test.
- **Drop and log at DEBUG:** a datum that cannot be mapped is dropped, never defaulted and never fatal — a bar missing any OHLC value, an option contract missing a 100 %-survey field, a detail list row missing its identifier (`RowMappers`), a downgrade (`InstrumentService`, with the `missing` list as a key-value). Structural breakage that leaves nothing sensible to return (incomplete chart metadata, a promised option chain with no `options` bucket) throws `YFDataException`.
- `MapperSupport` holds the shared helpers for the DTO mappers (`epochSecond`, `uri`, `zoneId`, `localDate`, `firstResult`). Reuse them; `assembly/build/Nodes` is the equivalent for `JsonNode` builders.
- **Testing is fixture-first and never touches the network.** Fixtures are real captures in `src/test/resources/fixtures/` (`instruments/v7_<SYM>.json` + `qs_<SYM>.json` per surveyed symbol — AAPL, PLUG, 005930.KS, BAC-PL, TTE.PA, SPY, GLD, CSPX.L, VFIAX, ^GSPC, BTC-USD, EURUSD=X, ES=F, RIDE — plus `options/`, one chart, one timeseries, search, lookup), refreshed by the `Capture*Fixtures` live tests. `testsupport/InstrumentFixtures` loads a symbol's v7 row / quoteSummary modules / `Payload` for builder tests; `testsupport/YahooDispatcher` routes every endpoint of a `MockWebServer` to those captures so a whole `YFinance.fromApis(...)` runs over real payloads (`YahooDispatcher.UNKNOWN` is a symbol no capture knows); `testsupport/Instruments` builds proof instruments (`Instruments.equity("AAPL")`); `testsupport/Fixtures` is the low-level `jsonResponse`/`api` pair for single-endpoint tests. A new field or endpoint needs a fixture, a failing test, then the implementation; assert request counts when the change touches the fallback.
- **Live suite and drift detector** (`src/integrationTest`, `@Tag("live")`, weekly via `live.yml`): `LiveYahooIntegrationTest` exercises every facade call through the real client; `GuaranteeDriftTest` classifies the 282-symbol survey list in one batch and fails, naming the missing field, if more than `max(1, 1 %)` of a class's live instruments downgrade. Never probe Yahoo with raw `curl`; captures go through `YahooClientFactory.apiClient(EndpointConfig.production())` in a live test.
- All errors are `YFinanceException` subtypes: `YFDataException` (→ `YFHttpException`, `YFMissingDataException` → `YFSkippedException`, `YFClassMismatchException`), `YFRateLimitException`, `YFAuthException`. Batches wrap them in `Outcome.Failed`; `Skipped` is for "Yahoo answered, nothing to return".
- **Nullness tooling:** every package is JSpecify `@NullMarked` (see each `package-info.java`). Unannotated = never null; DTO components are all `@Nullable` by design. Record accessors inherit component nullness, so a component normalised in a compact constructor (lists) stays non-null in its declaration. Prefer restructuring code (locals, a small helper) over `@SuppressWarnings("NullAway")`.
- **Logging:** SLF4J (`LoggerFactory.getLogger(X.class)`); `slf4j-api` is an `api` dependency and the only logging dependency — never add a backend to main. Tests bind Logback at WARN (`src/test/resources/logback-test.xml`) — not slf4j-simple, whose MDC is a no-op. Use the fluent API (`LOG.atWarn().log(...)`, `LOG.atLevel(level)...`); `{}` placeholders, never concatenation. **Context:** every service entry point wraps its work in `LogContext.scope(op, symbol)` (MDC keys `yf.op`, `yf.symbol`; the `LogContextInterceptor` adds `yf.endpoint` per HTTP call). The `op` names are `instruments`, `details`, `history`, `statements`, `options`, `search`, `lookup`, `fetch`; add a new one only for a genuinely new operation. MDC is thread-local, so anything that runs on a `FanOut` worker opens its per-symbol scope **on the worker** (see `DetailService.one`, `Tickers.fetchOne`), not only around the batch. Event facts (`status`, `attempt`, `delayMs`, `reason`, `cause`, `missing`) go as `addKeyValue(...)`, not into MDC. **Level discipline:** `WARN` only for degraded-or-gave-up (empty in a healthy run); `INFO` once per client lifetime or per multi-symbol batch (`batch.summary()`), never per symbol — the services log a one-symbol batch's summary at `DEBUG`, since `Ticker.instrument()`/`detail(...)` go through them; `DEBUG` once per request (`RequestLogInterceptor`), per downgrade or per dropped datum. Never log an exception the library also throws. Assert log output in tests with `testsupport.LogCapture`.
- **HTTP client:** `EndpointConfig.clientCustomizer` must be applied last in `YahooClientFactory` so users can override anything the library sets.
